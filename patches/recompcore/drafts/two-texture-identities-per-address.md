Item 07 candidate, adapted from elliotttate's `180f3896f8738cc2975c58486a66d694b3cbad61` (`gxcore_draw: keep two texture identities per guest address`). Human attribution is retained in the patch. It applies after the current eleven active patches and changes only `GXRuntime/graphics/aurora/lib/gfx/gxcore_draw.cpp`.

Each guest texture address keeps two recently used texture/palette identities. Content changes still replace the previous entry for that identity; a third identity evicts the less recent slot. Pending HD originals now follow the same ownership and eviction rules, while remaining outside generation hits so a completed replacement can be observed on the next draw. Reset clears both slot ownership and pending handles.

The actual source-derived cache/resolver, real Abseil hash map, XXH3, and GX decoder passed 420,637 checks in O3 and ASan. Tests compare decoded pixels against the unchanged resolver, exercise two/three palettes, texel/TLUT writes, cached/uncached aliases, unmarked small writes, failed dirty observers, non-CI normalization, EFB override invalidation, pending/ready/cancelled HD replacements, eviction, and reset. The authored two-palette control performs 1,000 uploads with the current cache and 2 with the candidate. GPU upload and HD-request resources are stand-ins; no game, GPU, display, audio, or input was invoked.

The first ASan link had an MSVC string annotation mismatch, and a later attempt exposed the layout mismatch between ASan hash-map headers and an uninstrumented Abseil implementation. Both negatives are retained. The passing ASan test uses the actual Abseil `raw_hash_set.cc` built with ASan and matching MSVC annotation settings. A subsequent offline closure omission for the already pinned `stl_asan.lib` was corrected without rerunning tests.
